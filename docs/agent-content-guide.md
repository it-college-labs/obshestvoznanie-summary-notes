# Инструкция для агентов: конспекты Нейроархива

Эта инструкция нужна для агентов, которые добавляют или редактируют статьи.
Сейчас весь контент живёт в PostgreSQL и редактируется через админку. MDX-файлы
в `src/content/notes` сохраняются только как исходный материал для миграции.

## Как попасть в админку

1. Открой сайт (локально `http://localhost`, на сервере — `${BASE_URL}`).
2. В архиве зажми долгим тапом/кликом правую точку заголовка окна или нажми
   `Ctrl+Shift+A`.
3. Введи пароль, который соответствует `ADMIN_PASSWORD_HASH` в окружении.

## Контентная единица

Одна тема курса = одна карточка недели = одна статья в БД. В админке на странице
создания/редактирования статьи нужно заполнить поля:

- `id` — стабильный латинский идентификатор, например `week-03-politics`.
- `week` — подпись недели, например `Неделя 3`.
- `title` — заголовок темы.
- `annotation` — живая аннотация на 1–2 строки.
- `tags` — 2–4 коротких тега.
- `accent` — ровно 3 цвета темы в формате `#rrggbb`.
- `folderPreviewImages` — ровно 3 URL изображений, которые показываются при
  наведении на папку. В админке они выбираются через карточки изображений:
  можно взять файл из загрузок или загрузить новый прямо в нужный слот.
- `botThinkingImage` — URL изображения, которое показывается в окне бота перед
  статьёй.
- `readingTime` — примерное время чтения, например `9 минут`.
- `content` — JSON-блоки редактора (см. ниже).
- `status` — `draft` или `published`. Опубликованные статьи видны на сайте.

## JSON-блоки редактора

Статьи состоят из блоков. В админке используется TipTap с кастомными блоками:

- Обычные абзацы и заголовки — основной текст.
- `<keyIdea>` — одна сильная мысль.
- `<definition>` — понятное определение термина.
- `<example>` — жизненный или учебный пример.
- `<callout>` — важное примечание.
- `<examTrap>` — типичная ошибка в задании, если в теме есть риск путаницы.
- `<compareTable>` — сравнительная таблица, только там, где она реально помогает.

Хороший ритм: 2–4 абзаца объяснения, затем одна смысловая вставка, затем снова
обычный текст. Статья не должна превращаться в набор плашек.

Длина статьи: обычно 700–1200 слов. Не раздувай текст ради объёма.

## Изображения

В редакторе статьи поля `folderPreviewImages` и `botThinkingImage` выглядят как
карточки изображений. Выбери файл из списка загрузок или загрузи новый прямо в
нужную карточку.

Технические требования к превью:

- вертикальный формат примерно 260×360 или близкий;
- без мелкого нечитаемого текста;
- три разных по смыслу изображения (например, термин, схема, ситуация);
- если настоящих ассетов ещё нет, временно используй placeholder из
  `public/assets/placeholders`.

## Аннотация, теги и цвета

Аннотация должна звучать как вход в тему, а не как сухой пункт учебника. Хорошо:
“Как общество удерживает порядок: нормы, санкции, мораль, право и тонкая граница
между привычкой и правилом.” Плохо: “В данной статье рассматриваются социальные
нормы.”

Теги короткие, 2–4 штуки. `accent` — три цвета, подобранные по смыслу темы, но не
один оттенок на все статьи.

## Проверка перед сдачей

После правок:

```bash
npm run lint
npm run build
```

Локально можно перезапустить стек и проверить статью на сайте:

```bash
./scripts/deploy.sh dev
```

Проверь, что:

- статья открывается по ссылке `/article/{id}`;
- папка в архиве показывает превью;
- бот-переход работает;
- в админке сохранение/публикация проходят без ошибок.

## Импорт старых MDX

Если нужно перезалить статьи из MDX-исходников, запусти:

```bash
ADMIN_PASSWORD="your-admin-password" node scripts/migrate-mdx-to-json.mjs
```

Скрипт логинится в админку и создаёт/обновляет статьи через API. Перед запуском
убедись, что backend запущен (например, через `docker compose up`).
